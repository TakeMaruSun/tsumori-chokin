# つもり貯金

ライブに落選した・遠征をやめた・グッズを我慢した……そのとき使うはずだったお金を「貯まったつもり」で記録するアプリ。スマホで使うのが前提。

「遠征用」「グッズ用」のように、用途ごとに入れものを分けられる（せってい →「用途ごとに入れものを分ける」をオン。既定はオフ。最大12個）。記録するときにどれに入れるかを選び、ホームではタブか左右スワイプで切り替える。入れものごとに目標金額と見た目を決める。

見た目は次の2つ。

- **ビン**：目標に向かって中身が増える
- **ガチャガチャ**：記録がカプセルになって積もっていく。カプセルの面積は金額に比例し、1 個は目標の 10% ぶんが最大（それを超える記録は 10% ずつの複数個に分ける）。最大のカプセル 10 個で満タン

目標額に届くと、入れものは棚に並び、次の入れものに切り替わる。

画面の色は「せってい → 推しカラー」で変えられる（9色＋じぶんで選ぶ）。選んだ色から、ライト・ダークそれぞれの配色を自動で作る。

## ファイル構成

| パス | 役割 |
|---|---|
| `index.html` | 編集用のソース（ここを直す） |
| `tools/build.py` | 公開用ファイルを `dist/` に書き出す |
| `tools/make_icons.py` | ホーム画面用アイコンを `icons/` に描く |
| `tools/sw.js` | オフライン用 Service Worker（基本的に変えない。版は `version.json` で管理） |
| `fonts/src/` | フォントの元データ（SIL OFL 1.1） |
| `dist/web/` | **スマホ向けの公開版**（Web に置く。オフライン対応・ホーム画面に追加できる） |
| `dist/つもり貯金.html` | PC 向けの単体版（フォント込みの 1 ファイル。ダブルクリックで開く） |

## 更新内容を書く

公開する前に `CHANGES.json` の先頭に 1 件足す（`rev` は 1 ずつ増やす。`items` は利用者向けの短い文、1 件 100 文字・20 行まで）。
ビルドが `version.json` に載せ、利用者が「更新を確認する」を押したときに、今の版より新しい分だけ表示される。

## 直したら

```
python tools/build.py
```

`index.html` を編集したら必ずビルドし直す。公開版にはスクリプトとスタイルのハッシュを使った CSP が入るため、ビルドし直さないと公開版のスクリプトが動かなくなる。

## セキュリティとプライバシー

- **通信しない**：外部のフォント・スクリプト・解析タグは使わない。CSP の `default-src 'none'` で、外部への通信と外部ファイルの読み込みをブラウザ側で禁止している。ビルド時に外部 URL や通信用 API の記述がないかも検査する
- **記録は端末の中だけ**：ブラウザの localStorage に保存し、どこにも送らない。サーバーには記録が届かないので、公開先から見えることもない
- **入力値は HTML として扱わない**：画面にはすべて `textContent` で入れる
- **バックアップの読み込み**：他の人から受け取ったファイルも想定し、5MB・2万件・カテゴリ40個の上限と、項目ごとの型・長さ・色コードの検査を行う
- **CSV 書き出し**：`=` `+` `-` `@` で始まる値の前に `'` を付け、表計算ソフトで数式として実行されないようにする

## 通信について（スマホ向け版）

- 初回だけ、アプリ一式（約3MB）を受け取って端末に保存する。以後は端末の中のものだけで動く
- **アプリの更新は自動では行わない**。「せってい → アプリの更新 → 更新を確認する」を押したときだけ `version.json` を見に行き、「更新する」を押したときだけダウンロードする。記録は送らない
- 「更新を確認する」では、今の版より新しい変更内容（`CHANGES.json`）を一覧で見せてから、更新するかを選べる
- 「更新する」の直前に、記録の控え（localStorage の `tsumori-chokin-snapshot`）を端末に取る。1 つ前の版も端末に残し、「前の版に戻す」で版と記録を更新前に戻せる（戻したあとは「更新する」で、取り直さずに新しい版へ戻れる）
- オンラインのときにアプリを開くと、ブラウザが `sw.js` に変更がないかを毎回確かめる（中身が同じなら数百バイトの「変更なし」の応答だけ。登録は `updateViaCache: "none"`、`_headers` で no-cache）。`sw.js` の不具合を直したとき、次に開いた時点で届くようにするため。アプリ本体はこれでは変わらない
- **非常口**：`<公開URL>/?reset` を開くと、アプリの保存分を最新版で取り直してから普通に開き直す（記録は消えない）。アプリが壊れて「更新する」が押せないときに案内する。電波がないときは案内の画面を出し、保存分は消さない
- `tools/sw.js` はむやみに変えないこと。中身が変わると、ブラウザが自動で新しい版の sw.js を入れる（保存済みのアプリ本体はそのまま使い続ける）

## 公開（Cloudflare Pages）

公開先は Cloudflare Pages の Direct Upload（GitHub・CLI は使わない）。無料プランで転送量・アクセス数の上限がなく、止まる心配がない。

1. Cloudflare にログイン →「Workers & Pages」→ 作成 →「Pages」→「アセットをアップロード（Upload assets）」（**Git に接続は選ばない**。あとから切り替えられない）
2. `dist/web` フォルダを**フォルダごと**ドラッグ → デプロイ

直したとき：`python tools/build.py` → Pages のプロジェクトの「新しいデプロイを作成」から `dist/web` を再度ドラッグ。URL は変わらない。
公開のたびに `<英数字>.<プロジェクト名>.pages.dev` という URL も増えるが、別のサイト扱い（記録も別になる）なので、人に教えるのは `<プロジェクト名>.pages.dev` だけにする。デプロイが増えすぎるとプロジェクトの削除が面倒になるので、まとめて出す。
利用者側は「せってい → 更新を確認する」で新しい版になる（自動では更新されない）。

注意：Cloudflare Pages は `/index.html` を `/` へ 308 転送する。`tools/sw.js` は転送つきの応答を作り直して保存する（転送つきのままだとページ表示に使えず、2回目以降に開けなくなる）。

## 共有のしかた

- スマホ：`dist/web/` を HTTPS で公開し、URL を送る。受け取った人は一度開いて「ホーム画面に追加」すれば、以後は機内モードでも使える
- PC：`dist/つもり貯金.html` をそのまま渡せばよい

記録は人ごと・端末ごとに別々で、共有されない。検索エンジンには載らない設定（`noindex`・`robots.txt`）にしてあり、URL を知っている人だけが使う想定。
